# WealthNX - Performance and Adaptive System audit (read-only)

Method: static code scan + live DOM measurements on http://localhost:3333 (dev server, own tab, widths 320/375/768/1024/1440/1920/2560, tab reset + closed). No repo file touched.

## Measurement caveats (read first)
- The Browser tab was a BACKGROUND tab (`document.visibilityState = hidden`): LCP entries were empty. LCP is therefore UNVERIFIED; CLS entries were available (home 0.0026, /features/ 0).
- In the resize emulation, media/container queries followed the width but `vw` units did NOT (a `clamp(30px,3.4vw,50px)` heading stayed at 48.96px = 3.4 x 1440 at a 320 viewport). So live font sizes of every `vw`/`clamp(vw)` rule below 1440 are UNVERIFIED; verify in a real window / DevTools device mode.
- Dev build: script transfer (~2.6 MB) is dev-mode, not representative. `out/` is STALE (built 2026-10-05, 127 MB, lacks /blogs, /compare, /why-wealthnx), so bundle sizes below are estimates.
- Correction to the "known context": (a) Inter IS loaded (see 2); Montserrat is declared but no text uses it. (b) Lenis is NOT running: `window.lenis` is false, `lenis` and `gsap` are in package.json but imported nowhere in app/src/components. Native scrolling is active.

## 2. Fonts (corrected)
Live: `document.fonts` shows Inter 400/500/600/700 latin loaded from gstatic (one 47 KB woff2 variable file, 484 ms) and Montserrat 300-800 all "unloaded" (declared, never used by any rendered text: 257 of 266 text nodes compute `Inter`). Not loaded in this audit: Caveat (falls to Segoe Script), and anywhere offline/blocked (CN, strict networks, privacy extensions) every page drops to Arial, i.e. the "Arial" fallback the letter-spacing hacks compensate for. The stack `Inter, Arial` also means a flash/swap (display=swap) shift on slow networks.
Recommendation (ponytail: smallest change):
1. `app/layout.jsx`: replace the 3 `<link>` tags with `import { Inter } from 'next/font/google'; const inter = Inter({ subsets:['latin'], display:'swap', variable:'--font-inter' });` and `<html className={inter.variable}>`. next/font downloads at build and self-hosts the file into `out/_next/static/media` (works with `output:'export'`). One request, same origin, preloaded, with size-adjusted fallback (`adjustFontFallback`) -> removes the swap shift.
2. Drop Montserrat (no text uses it) or load only if a section truly needs it; remove `--font-montserrat` in globals.css:2 and the 101 `font-family:'Montserrat'...` declarations (they resolve to Arial/Inter anyway).
3. `.home-redesign{font-family:Arial}` (HomeRedesign.css:1) overrides sections that do not set a font: insights section (hr-ins) renders Arial; change to `inherit`/`var(--font-inter)`.
4. Caveat: add `Caveat({subsets:['latin'],weight:['400'],variable:'--font-caveat'})` and use it in `--hw2-hand` (HomeWhy.css:27) or drop the handwritten note.
5. Effect on text widths: Inter is wider than Arial by ~1-3% at body sizes. Sections tuned with negative letter-spacing (`-.068em`, `-.065em`, `-.05em` in hero/h2s) were measured against the rendered font. Since Inter is already what renders for online users, no re-tuning is needed; only offline fallback differs. `next/font` fallback metrics make the fallback match Inter, which is a net improvement. Verify wrapping of hero/h2s at 1440 and 375 after the change.

### 4.4 Fluid sizing system and fixed-px sections
Home sections already use the Figma-unit pattern (`N * var(--u)` with `--u = 100cqw/frame`): HomeWhy (149 uses), HomeWhyPanels2 (287), HomeVoices (78), BlogsPage (178), CompareDetail (119), HomePortfolio (36), HomeDownload (22). Still fixed-px (no cqw/--u/clamp ratio to speak of; px counts from the table): `HowItWorksLanding.css` (345 px values, 2 clamp), `PricingRedesign.css` (298 px, 8 clamp), `HomeRedesign.css` legacy (633 px), `GenieLanding.css` (219 px, 4 clamp), `CompareLanding.css` (215 px, 14 clamp), `FeatureDetailTemplate.css` (222 px, 3 clamp: orbit 930x735px, hero 650px min-height, carousel arcs), `TopBar.module.css` (146 px), `SiteFooter.css` (66 px), `SupportChat.css` (117 px, 0 clamp), `ContactLanding` (partly cqw, 25). These render as a fixed-size layout between roughly 1000 and 1920: it will look small and left-clustered at 1920+ (feature `fdt-orbit` is `min(930px,100%)`, hero grid fractions only) and tight near 1000-1100. At 1440 they match design; at 1920 section widths stretch while type/art stay at px size.
Proposal (reuse what exists): make a page-level container per page: `container-type:inline-size` on `<main>`/page root, one token `--u: calc(100cqw / 1440)` (home sections keep their own Figma frame values), and convert in this order of impact: (1) type via `clamp(min, calc(N*var(--u)), max)` with max = N*1.25 so ultra-wide does not balloon; (2) paddings/gaps with the same calc; (3) fixed art sizes (`width:930px` etc.) to `min(930px, 62cqw)`. Cap content width with `max-width:1920px;margin-inline:auto` (and `body{background:var(--night)}` to hide edges) so 2560 does not stretch. Stop short of rewriting legacy app.css pages.
Floor: cqw scaling is also what drives tiny mock-UI text: hw2 (How/Why mock panels) renders 6.4-9.3 px text at 1440 (22 elements at 320 min 7 px), `ha` 9.7 px (6), `hc` 7-8.6 px (8); how-it-works mock UI 6-8.5 px (69 text nodes < 11px at 375, min 6 px: hw-stat, hw-genie__ai 6.5, hw-projection__tabs 7); blogs chip 5.9 px (`.bl-chip-w`); compare detail min 7.15 px.
